# PVM VM遇到异常时的路径，例如page_fault

#date 2026-09-01 09:37:05
## PF handler define

```
// page fault HANDLER 函数定义
DEFINE_IDTENTRY_RAW_ERRORCODE(exc_page_fault)
```

`DEFINE_IDTENTRY_RAW_ERRORCODE` 定义:
```
#define DEFINE_IDTENTRY_RAW_ERRORCODE(func)				\
__visible noinstr void func(struct pt_regs *regs, unsigned long error_code)
```

## PF handler declare
```
DECLARE_IDTENTRY_RAW_ERRORCODE(X86_TRAP_PF,    exc_page_fault);

#define DECLARE_IDTENTRY_RAW_ERRORCODE(vector, func)			\
	DECLARE_IDTENTRY_ERRORCODE(vector, func)
```

`DECLARE_IDTENTRY_ERRORCODE`有两组定义:
* 在`__ASSEMBLY__` 编译条件下
* 不在`__ASSEMBLY__`编译条件下

### 不在`__ASSEMBLY__` 编译条件下
我个人理解这个是函数声明，也就是C程序如果包含这个头文件，则有这个符号的类型声明，用于编译`.c`
```cpp
#define DECLARE_IDTENTRY_ERRORCODE(vector, func)			\
	asmlinkage void asm_##func(void);				\
	asmlinkage void xen_asm_##func(void);				\
	__visible void func(struct pt_regs *regs, unsigned long error_code)
```

### 在`__ASSEMBLY__`编译条件下

这个一般用于汇编展开，而源于 `asm_xxx`的定义，也在这个宏里面展开，所以其不仅仅是符号声明，更是关于这个符号的定义:
```cpp
#define DECLARE_IDTENTRY_ERRORCODE(vector, func)			\
	idtentry vector asm_##func func has_error_code=1
	
.macro idtentry vector asmsym cfunc has_error_code:req
SYM_CODE_START(\asmsym)
    ...
	idtentry_body \vector \cfunc \has_error_code
	
.macro idtentry_body vector cfunc has_error_code:req
    ...
    //如果发现 host_rsp不为0，说明是从PVM guest mode跳转过来的
	cmpq	$0, TSS_extra(host_rsp)
	jne	.Lpvm_idtentry_body_\@
.Lpvm_idtentry_body_\@:
    //CS 的最低两位表示 RPL, 表示特权级.
    testb	$3, CS(%rsp)
	/* host exception nested in IST handler while the switcher is active */
	//如果最低两位是0，则表示已经在 最高特权级了, 这可能是之前已经进入到异常处理程序，还
	//没来得及切 host_rsp结果又出现异常了
	jz	.L_host_idtenrty_\@

	.if \vector < 256
	movl	$\vector, ORIG_RAX+4(%rsp)
	.else // X86_TRAP_OTHER
	/*
	 * Here are the macros for common_interrupt(), spurious_interrupt(),
	 * and XENPV entries with the titular vector X86_TRAP_OTHER. XENPV
	 * entries can't reach here while common_interrupt() and
	 * spurious_interrupt() have the real vector at ORIG_RAX.
	 */
	movl	ORIG_RAX(%rsp), %eax
	movl	%eax, ORIG_RAX+4(%rsp)
	.endif
	//准备切换到hypervisor
	jmp	switcher_return_from_guest
```

> [!summary]  所以，关于 PVM VM 被动接收event, 或者主动触发异常，并没有switcher直接切换，而是直接切换到 hypervisor（走vm-exit)处理

# `pvcs->event_vector & 0xFF00` 表示什么

* STD
* NMI
* MCE
