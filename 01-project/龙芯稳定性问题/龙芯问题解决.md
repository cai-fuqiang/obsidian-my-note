## 继续推进

我们以 `info registers -a`命令中的`r1` regs, 和`queued_spin_lock_slowpath`中保存的r1 为准。推导下第一个参数:

| 命令                | 值                | 符号地址                  |
| ----------------- | ---------------- | --------------------- |
| info registers -a | 90000000003599a8 | hrtimer_interrupt+816 |
| 堆栈                | 90000000003597c0 | hrtimer_interrupt+328 |

附近汇编:

* info registers -a
	```
	0x90000000003599a0 <hrtimer_interrupt+808>:     move            $a0, $s7
    0x90000000003599a4 <hrtimer_interrupt+812>:     bl              19879100        
    #   0x900000000164ee60 <queued_spin_lock_slowpath>
    ```

* 堆栈
   ```
   0x90000000003597b8 <hrtimer_interrupt+320>:     move            $a0, $s7
   0x90000000003597bc <hrtimer_interrupt+324>:     bl              -5452   
   # 0x9000000000358270 <__hrtimer_run_queues>
   ```
   
**可以看到都是 `$s7` 寄存器**

s寄存器为save寄存器，如果在函数执行过程中，用到了该寄存器，会在函数调用开始时，将寄存器值压入堆栈，以便在函数返回时重新load，这样可以保证`A()->B()`后， save寄存器的值都是不变的。

而`queued_spin_lock_slowpath()` 并未在函数开始时，保存寄存器:

```
0x900000000164ee60 <queued_spin_lock_slowpath>: move            $t0, $ra
0x900000000164ee64 <queued_spin_lock_slowpath+4>:       nop
0x900000000164ee68 <queued_spin_lock_slowpath>: addi.d          $sp, $sp, -48
0x900000000164ee6c <queued_spin_lock_slowpath+4>:       st.d            $s0, $sp, 32
0x900000000164ee70 <queued_spin_lock_slowpath+8>:       st.d            $ra, $sp, 40
0x900000000164ee74 <queued_spin_lock_slowpath+12>:      move            $s0, $a0
0x900000000164ee78 <queued_spin_lock_slowpath+16>:      b               488     # 0x900000000164f060 <queued_spin_lock_slowpath+504>
0x900000000164ee7c <queued_spin_lock_slowpath+20>:      li.w            $t0, 256
```

只保存了`s0`寄存器, 

`$s7` 寄存器为`r23`，该寄存器值为: `0x900000000176fd40`（前面提到过，为`hrtimer_bases`地址 **(未加 percpu offset)**

查看代码，看下percpu变量如何计算:
```
#define this_cpu_ptr(ptr)>      raw_cpu_ptr(ptr)

#define raw_cpu_ptr(ptr)						\
({									\
	__verify_pcpu_ptr(ptr);						\
	arch_raw_cpu_ptr(ptr);						\
})


#define arch_raw_cpu_ptr(ptr) SHIFT_PERCPU_PTR(ptr, __my_cpu_offset)

#define __my_cpu_offset					\
({							\
	__asm__ __volatile__("":"+r"(__my_cpu_offset));	\
	__my_cpu_offset;				\
})

register unsigned long __my_cpu_offset __asm__("$r21");
```

可以看到为寄存器 `$r21`, **而 cpu3 的`r21`为==0==**

查看 所有vcpu的 `r21`, 只有CPU 3 的 r21 是0

**那crash 是如何打印出 cpu 3 的 percpu var地址的呢? 另外，目前的crash 并未能获取任何 cpu的 cpu列表**

`set_my_cpu_offset()`可以设置`r21`

```
static inline void set_my_cpu_offset(unsigned long off)
{
	__my_cpu_offset = off;
	csr_write(off, PERCPU_BASE_KS);
}
```

其会在`smp_prepare_boot_cpu()` 和 `start_secondary()`中分别为 boot cpu 和 secondary cpu 调用。

以start_secondary为例
```
start_secondary
  set_my_cpu_offset(per_cpu_offset(cpu))
  #define per_cpu_offset(x) (__per_cpu_offset[x])
```

其是从`__per_cpu_offset[]` 数组中获取的。
