# 跨代热迁移
## host-model/host-custom
如果使用host model 或者custom的模式，跨代热迁移没有什么问题。所以，**我们后续==新创建的虚拟机的cpu类都使用 custom==，这样在跨代热迁移时，会获得非常好的兼容性**. (我们现在hygon环境试点)
### 定义虚拟机cpu类型

我们使用
```
virsh capabilities | virsh cpu-baseline /dev/stdin
```
命令来获取 host-model的 cpu 类型，以及feature。 [[01a-hygon3G-4G-host-model-feature#hyogn3G| hygon 3G例子]]
### 如何判断host A节点host-model 启动的虚拟机能否迁移至 host B

1. 在host A 执行 `virsh capabilities | virsh cpu-baseline /dev/stdin > source.xml`
2. 将上面命令生成的文件copy到host B : `scp source.xml root@$host_B:/tmp/`
3. 在host B执行 `virsh cpu-compare /tmp/source.xml`

我们来验证下:
* 以`3G->4G`为例
```sh
[root@11-213-1-166 18:48:15 wangfuqiang49]# virsh cpu-compare 3G.xml
Host CPU is a superset of CPU described in 3G.xml
              ^^^^^^^^
```
这样就说明没有问题。

以4G->3G为例
```sh
[root@A06-R08-I203-67-3757056 ~]# virsh cpu-compare 4G.xml
error: Failed to compare host CPU with 4G.xml
error: internal error: Unknown CPU feature stibp-always-on
```

可以发现4G中虚拟机的某些feature在3G中并不支持。

# host-passthough
那现存的 `host-passthough` 的虚拟机怎么办呢？

* **source**: hygon3G host-passthough
* **dst**: hygon4G custom a **specified model**

我们在目的端启动虚拟机时，使用一个自定义的 cpu model (需要在qemu 侧新增cpu model，并且需要保证目的端使用该cpu model 启动的虚拟机，需要和源端使用 host-passthough 启动的虚拟机，cpuid列表均相同). 

***

我这边定义了`hygon-7390` cpu model，目的端 xml 定义为:
```xml
<cpu mode='custom' match='exact'>
  <model fallback='forbid'>hygon-7390</model>
  <vendor>Hygon</vendor>
</cpu>
```
